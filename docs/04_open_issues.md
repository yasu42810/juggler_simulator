## 3. 設計で決めたこと（参考）

| 決定 | 理由 |
|---|---|
| 設定5 の BIG 確率は 1/240.1 | 北電子公式（Ⅵ）の値と一致。合算 1/126.8 とも整合 |
| ぶどうは独立近似ではなく、台の BIG・REG 回数を条件にした式で計算する | 遊技区間内のボーナス回数を入力させなくても、超幾何分布を使ってモデルの中で厳密に計算できる。独立近似との差は試算した4ケースで最大 0.44 ポイント。実戦モードでは区間のボーナス回数が分かるので、さらに単純な式になる（内部設計 §4.3） |
| REG 内訳は「分類できた REG の中の単独の割合」として計算する | 「不明」を抽選のカテゴリとして扱うと REG を二重に数える。この方式なら全件不明のとき内訳なしと完全に一致する（内部設計 §4.4） |
| 既定の事前分布は Web の情報を参考に決めた仮定「標準（低設定中心の想定）」 | 業界メディアの実データ（導入直後2週間）と個人ブログの推定を、決まった手順で組み合わせた。全国の実態の推定ではないので、名前でも「想定」と示す（調査メモ setting-distribution.md） |
| BIG・REG は常に計算に使い、ON/OFF はぶどうだけ | 片方を外すとモデルと説明が複雑になる（内部設計 §4.5） |
| 機種の違いは「データ追加」と「モデル追加」の2段階で吸収する | 確率の値だけ違う機種はデータだけ、判別要素が違う機種はモデルのモジュールだけを足す。画面はモデルの宣言から作る（内部設計 §4.7） |
| 実戦モードの事後確率は、総回転数を入れ直した時点（スナップショット）でだけ計算する | 古い回転数と新しいぶどう回数を混ぜると、ぶどう確率が実際より良く見えるため（外部設計 §11.2） |
| マイジャグラーⅥ は別機種として扱う | 同じボーナス確率でも、小役の解析値などが違う可能性がある |
